# Decisions: spec versus existing code

Every entry keeps working behaviour where the spec conflicted with code. Touched files are listed so reviewers can verify.

- Model env var: STATUS_REPORT and HEAD hard coded llama-3.3-70b-versatile in config.py and query/entities.py. Working tree already switched both to env driven openai/gpt-oss-120b. I preserved that fix in Phase 1 instead of reverting to HEAD. Files: config.py, query/entities.py, .env.example.
- Requirements pins: Working tree pinned exact versions and dropped legacy ML deps, while HEAD still lists streamlit, sklearn and xgboost. I preserved the pinned runtime list, then Phase 2 moved it to pyproject.toml with uv.lock. Files: pyproject.toml, uv.lock.
- CLI encoding: CLI advice crashed on Windows consoles. Working tree added utf8 reconfigure for stdout and stderr. Preserved. Files: entrypoints/cli.py.
- Legacy removal: app1.py, train.py, Regressor.pkl, notebook, pbix and root CSV are unused by the import graph from entrypoints/api.py and entrypoints/cli.py. Removed with git rm in Phase 1. Pipeline, scraping, eval, data and sql were left untouched per instructions, even though backfill scripts have a broken lagos_property_scraper import and check_dedup.py is a debug viewer.
- Status report: STATUS_REPORT.md was untracked and gitignored, and its claims about missing .env.example, uncommitted observability and dead model were stale after Phase 1 and 2. Folded the still valid findings into README in Phase 3 and deleted the file from disk. No history rewrite.
- Annualisation: Query engine treats null period as annual. That can silently mix monthly and yearly rows when scraper period detection fails. Phase 4A documents this and excludes invalid or non positive prices and duplicates, but it does not change scraper period logic, which needs page level investigation. Files: query/stats.py, query/query_engine.py.
- Property buckets: Existing property_type values are free text. Phase 4A maps self contain by substring and 1, 2 and 3 bedrooms by bedroom count for the breakdown. Other bedroom counts return null for that bucket rather than inventing data. Files: query/stats.py, query/answer.py.
- Response shape: Existing /query returned legacy dicts used by CLI. Phase 4A keeps legacy keys and adds answer with version 1, headline, breakdown, median, confidence, request id and latency. CLI still prints legacy message and results. New SSE and async chat endpoints use the same contract. Files: entrypoints/api.py, query/answer.py.
- Clarification: Spec says do not ask clarification when overall stats exist. Implementation only asks clarification for lookup with no area, beds, property type or budget. All other no data paths return no_data with counts. Files: entrypoints/api.py.
- Ruff scope: pyproject.toml selects E, F, I, W, UP, B. Whole repo still has pre-existing style debt. Phase 4A to 5 fixed ruff on every file touched in those phases with safe autofixes and two manual fixes, without reformatting untouched files. Files: pyproject.toml, plus each touched source file.
- Analytics migrations: No Alembic was in use. Used numbered SQL files applied by uv run python -m entrypoints.cli migrate. area_freshness is a view. admin_users plus admin_sessions and login_attempts support real auth. Files: sql/migrations, analytics_logging.py.
- Logging privacy: question_events has no IP column. log_question truncates raw question to 4000 characters and never stores request IP. Files: analytics_logging.py, entrypoints/api.py.
- Admin auth storage: Argon2 hashing with HttpOnly Secure SameSite Lax session cookie, server side expiry, in-memory lockout with DB fallback sessions. CSRF uses constant time comparison on X-CSRF-Token. Files: admin/auth.py, admin/api.py.
- Scrape concurrency: Threading lock gives single run per process plus DB row per run. True multi worker DB advisory lock is still future work for hosted scale. Cooldown is 60 seconds. Files: admin/api.py, scraping/runner.py.
- Frontend budget: Tailwind v3 was pinned because Tailwind v4 needs the separate PostCSS plugin. React 19 from Vite scaffold satisfies React 18 plus. Bundle check counts JS gzip only: about 99 KB against a 120 KB budget. Files: frontend/package.json, frontend/vite.config.ts.
